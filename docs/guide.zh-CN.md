# 使用与实现

[返回 README](../README.md) | [English](guide.md)

## 操作

菜单栏显示 CPU 使用率、CPU 温度和内存使用率。点击展开 CPU/GPU/内存读数，悬停或点击任一读数会在左侧打开本地详情小窗（左侧空间不足则放右侧）。详情包含最近两分钟实际采样趋势；CPU 展示每核使用率和进程排行，内存展示分类占用、交换空间和排行，GPU 不提供未经验证的进程归因。移入详情窗可继续查看，移开后收起；不触发模型调用。底部输入问题并发送，即进入聊天窗口。点击外部或按 Esc 收起面板；输入时移出鼠标不会关闭。草稿在本次运行内保留。概览和聊天顶部均可打开“进程列表”：本地查看所有可读进程，支持名称/PID 搜索，按内存、CPU、线程数或名称排序；每 2 秒刷新，关窗、最小化及休眠时暂停。线程数是每进程线程总数，不是逐线程占用。选择进程可询问助手，或直接请求正常退出可识别的前台应用（仍需确认）。聊天可停止检查、开启新对话、展开具体进程依据、选择文件或配置模型。聊天窗口关闭会取消当前模型请求，文字与回执保存在本机历史。

刷新间隔固定为窗口关闭时 5 秒、打开后 2 秒，不提供设置项或界面频率提示。设置包含登录启动和退出。登录启动默认关闭，只有点击才注册。基础监控无需模型或网络。

## 模型设置

先安装原生 Codex 或 Claude Code CLI。Claude 默认登录模式需先在终端完成登录。初始选择 Claude Code。在“模型设置”选择助手；CLI 路径留空会查找常用安装目录，模型留空使用 CLI 默认。Codex 必须在 TinyStat 配置自定义服务商，不共享终端登录，不加载用户 config.toml。使用兼容服务商时勾选“自定义服务商”，填 HTTPS 地址、模型和密钥：Codex 使用 Responses 兼容 API，Claude 使用 Anthropic 兼容 API，可选 x-api-key 或 Bearer。

密钥仅保存到 Keychain 的 `TinyStat Assistant Provider` 条目，运行时注入 CLI 环境；不写入偏好或日志。留空只保留相同地址、CLI 和鉴权方式已有的密钥；切换服务商不会沿用旧密钥。TinyStat 不读取 tiller 的配置或密钥。Codex 使用独立临时目录和显式服务商密钥，不创建共享登录链接或恢复凭据副本。设置不验证远端连通性；发送失败会明确显示错误，基础监控继续工作。

Claude 默认模式使用自己的登录/凭据机制；CLI 自身可能按供应商策略产生运行元数据。TinyStat 禁止模型的 shell、外部 MCP 和文件操作能力，Claude 使用安全模式；需要支持这些参数的近期 CLI。已核验本机 Claude 2.1.295。模型版本、账号权限、兼容端点仍需实际连接验证。

## 诊断与操作

本轮问题与历史、证据分开传递。助手按需申请刷新概览、在本机按名称/PID 搜索（最多返回20个匹配）、查父进程关系、短时观察 CPU/内存，或读取已选择的 UTF-8 文本（最多8 KiB）。原生授权窗展示本批对象、用途及接收结果的模型服务商；取消后不执行。每个问题最多2批、每批3项检查，最多3次模型调用。普通解释无需重新采样。进程离开排行榜不代表退出，同名不代表同一应用，父子关系也不证明应用归属。

刷新概览包含 CPU/内存前8的并集、选中对象、覆盖信息、有效换页速率及最多24个系统历史点。授权窗说明系统快照及发现的进程身份可在当前会话复用；文件正文和其他详细补查结果只用于当前问题。不读取命令参数、浏览器标签、打开文件清单或端口。选择文件只登记路径和大小，正文读取与发送需要另外授权。模型身份区分用户配置与 CLI 上报，不把自述当服务商实际型号的独立证明。

“历史”可继续、重命名、确认删除本机记录。文字与操作回执保存于 `~/Library/Application Support/TinyStat/Conversations`，目录0700、文件0600；文字可能含用户输入和模型引用的私人内容。原始证据、文件正文、授权和可执行操作卡不落盘。最多30个会话，每个最多200条/256 KiB，超限明确提示，不自动删除。发给模型仅保留最近24条/24 KiB，省略旧消息会明确标记，不能称为摘要。界面每页40条、最多60个实时消息行。关窗释放消息视图和检查对象；恢复历史会重置授权、文件选择和保护规则，并明确提示。没有后台模型调用。

写入操作另行确认：应用正常退出；符合保守资格的当前用户后台进程可发送 SIGTERM（不会强杀，可能中断工作，不保证子进程或自动重启服务停止）；所选文件可移到废纸篓；模型生成文本完整预览后，可由你选择新位置另存。另存用独占创建，不覆盖已有文件；写入失败的部分新文件保留并报告。无任意 shell、提权、批量扫描或永久删除所选文件。短时观察不能证明泄漏或 GPU 进程归因。

## 指标口径

- 总 CPU 按全机 100%；进程 CPU 按单核 100%，多线程可超过 100%。
- GPU 使用率读取驱动 `Device Utilization %` 的采样值，不是整个 2/5 秒刷新间隔的平均值；0 表示驱动本次报告为零，不能据此断言整个间隔没有 GPU 工作，缺失显示 —。
- CPU/GPU 温度取映射 M1 SMC 最高有效值，不含 HID；M1 Max 核验 CPU 33 项、GPU 9 项。`*` 为部分覆盖；缺失不当作零。
- 状态优先使用系统热状态、内存压力；持续高 CPU 是另一个提示，不凭温度单独判断过载。
- 已用内存 = max(0, internal − purgeable) + wired + compressed；容量为 GiB/MiB。进程内存为 physical footprint；GPU 统一内存不能重复相加。

## 资源与隐私

监控使用串行采样队列和带 500ms 宽限的定时器。温度随有效基本采样更新，GPU 使用率随基本采样持续保存最近两分钟历史，GPU 温度在面板或主动检查时采集。刚启动或休眠后缺少的历史不补造。休眠/屏幕关闭时停止监控并取消检查。诊断进程采样独立，不修改菜单栏 CPU 增量基线。模型请求限制 120 秒、输出 1 MiB；取消、超时和退出会结束所拥有的进程组。聊天开销主要包括外部 CLI，不包含在应用包体内。

SMC 只有只读 key-info/read，不改变风扇或硬件。偏好保存于 `local.tinystat.app` 用户域。参考来源见[第三方说明](../THIRD_PARTY.md)。

## 构建与验证

运行 `bash scripts/build.sh` 生成本地 ad-hoc 签名的 `build/TinyStat.app`。退出旧实例后 `open build/TinyStat.app` 可预览；`bash scripts/install.sh` 安装到个人 Applications，备份旧包，不替换正在运行的版本。卸载前关闭登录启动，退出后移到废纸篓；偏好、备份和 Keychain 条目不会自动删除。

```sh
bash scripts/check.sh
bash scripts/verify.sh                 # M1 Max 实机读数与采样
bash scripts/verify-assistant.sh       # 无模型调用，测试操作/取消等边界
bash scripts/verify-assistant-live.sh claude # 可选，发送合成问候，消耗模型额度
```

实机验证范围是 M1 Max / macOS 26.4。其他芯片、旧版 CLI、长期睡眠恢复、启动项和多屏仍需进一步验证。[性能方法与历史数据](performance.md)。


助手权限、原生 CLI 沙盒及认证限制见 [安全边界](assistant-security.md)。Codex 需显式配置自定义服务商；默认 Claude 登录失败时需先在 CLI 完成登录。
