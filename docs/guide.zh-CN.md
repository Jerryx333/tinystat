# 使用与实现

[返回 README](../README.md) | [English](guide.md)

## 操作

菜单栏显示状态、CPU 使用率与温度、内存使用率。点击展开，移出面板或点击外部收起。点击 CPU/GPU/内存行进入同一详情页；进程排行切换 CPU 或内存。更多指标默认收起，小屏可滚动。设置可切换展开时的 5/10 秒刷新、登录启动和退出；外观跟随系统。

登录启动默认关闭，仅点击设置才注册。该功能、跨屏切换和长期睡眠恢复尚未做完整跨环境验证。首次启动 CPU 需要两个样本计算增量；进入 CPU 进程排行也需等待下次刷新。

## 指标口径

- 总 CPU 按全机 100%；进程 CPU 按单核 100%，多线程可以超过 100%。
- CPU/GPU 温度为各自已识别传感器最高值（M1 映射 CPU 10、GPU 4）。`*` 表示覆盖不完整；失败显示不可用。温度不能单独用来判定过载。
- 状态优先使用 macOS 热状态、内存压力；采样 CPU 持续至少 10 秒高于 90% 提示繁忙。
- 已用内存 = 应用 + 有线 + 压缩；应用取 internal − purgeable。容量使用二进制换算，但界面标签为 GB/MB。缓存为 purgeable + external 的可回收估算。
- GPU 使用系统统一内存，不能与已用系统内存重复相加。
- 进程内存为 physical footprint。最多读 4096 个可访问进程，超出显示截断；权限不足或退出的进程显示在覆盖计数中。只对前五名查询名称，以 PID 和启动时间避免进程复用。
- 更多指标包括每核负载、平均负载、运行时间、GPU 内存、应用/有线/压缩/缓存以及 swap 换入换出速率。首样本未知的速率显示横线。

## 资源与隐私

一个串行采样队列、一个带 500ms 宽限的定时器。收起每 10 秒、展开默认 5 秒，CPU 温度每 10 秒一组；GPU 每次展开先读一次，之后每 10 秒一组；计时器调度可能使实际间隔稍长。GPU 只在概览或详情可见时采集；进程仅详情可见时采集；每核仅更多指标展开时采集。短间隔基础采样复用近期样本；重新展开仍会触发 GPU 读取；指针退出使用事件，不持续轮询。休眠或屏幕关闭时停止采样。

趋势仅在内存保留最近两分钟、最多 64 点，无数据库、网络请求、常驻子进程或定时 shell 调用。正常运行不写日志；基准测试显式写报告。偏好保存在 `local.tinystat.app` 用户域。

SMC 采用只读 key-info/read 命令，不改变硬件或风扇设置。接口没有公开稳定性保证。参考来源见[第三方说明](../THIRD_PARTY.md)。

## 构建、更新与卸载

运行 `bash scripts/build.sh` 生成 `build/TinyStat.app`，仅本地 ad-hoc 签名。`bash scripts/install.sh` 安装至 `~/Applications/TinyStat.app`，相同版本重复运行无副作用；正在运行时拒绝替换。旧包备份到 `~/Library/Application Support/TinyStat/Backups`，失败的暂存路径会报告，不静默删除数据。

卸载前在设置中关闭登录启动并退出，然后将个人 Applications 中的 TinyStat 移到废纸篓。可选删除 TinyStat 的用户偏好和备份；卸载不会自动删除它们。源码目录与基准测试报告也不会自动移除。

## 菜单栏位置与诊断

首次启动使用右侧初始位置与固定项目标识；之后遵循用户保存的位置。Command 拖动可调整。第三方管理器的隐藏分区仍然有效；不清空其配置。

先退出 TinyStat，再执行 `"$HOME/Applications/TinyStat.app/Contents/MacOS/TinyStat" --diagnose-status`，两秒后输出菜单栏位置与屏幕范围，看完按 Ctrl-C 结束。已有实例运行时新实例会直接退出，不输出诊断。仅显式开启时输出；如需提交问题，请先去掉私人环境信息。

## 测试

`bash scripts/check.sh` 构建并检查签名/文档；`bash scripts/verify.sh` 还会读取本机传感器、用真实 CPU 工作量对照 getrusage、检查快速采样、排行切换、重开与重置。后者要求经验证的 M1 Max 传感器完整可读，虚拟机/其他型号不应视为通过。

[性能测量](performance.md)包括六种场景和固定工作负载对照。启动项、其他芯片和多屏环境仍需实际验证，模拟状态测试不证明这些环境兼容。
